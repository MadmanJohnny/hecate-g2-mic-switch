# 排错指南

## 先看日志

程序的所有判断都会写进日志，绝大多数问题看日志就清楚了。

| 运行方式 | 日志位置 |
|---|---|
| 打包版 exe | `%APPDATA%\HecateG2VoiceBridge\g2_bridge.log` |
| 源码运行 | 项目根目录下 `g2_bridge.log` |

界面版有「日志」页可以直接看，也有「打开日志文件」按钮。

正常工作时日志长这样：

```
[05:31:45] HECATE G2 麦克风开关 → 输入法语音输入（v2 电平判定）
[05:31:46] 麦克风采集正常，启动实测峰值=1 → 开关在【静音】
[05:31:46] 已连接 HID 接口：VID_2D99&PID_0026&MI_03\...
[05:32:05] 第 1 次切换 → 【麦克风开】(峰值=237) → 开始语音输入
[05:32:09] 第 2 次切换 → 【静音】(峰值=1) → 停止语音输入
```

## 问题 1：拨动开关完全没反应

**逐层排查。**

**① HID 事件有没有收到？**
界面版看「日志」页；命令行版看控制台。拨动开关时应该出现
`第 N 次切换 → ...` 或 `峰值=xxx，位置未变化（重复/抖动事件，忽略）`。

如果一行都没有，说明连 HID 报告都没收到：

```bash
python tools/hid_probe.py watch 0     # 然后拨开关
```

- 有输出 → HID 正常，问题在后面几步；
- 没输出 → 可能是耳机型号不同（HID 接口结构不一样），
  或者开关是**纯硬件断电式**的（根本不发 HID 报告）。

**② 麦克风采集是否正常？**

```bash
python src/g2_voice_bridge.py --probe
```

- 报 `waveInOpen 失败` → 麦克风被别的程序独占了，或默认录音设备选错了；
- 三次峰值都是 0 → 麦克风没声音，检查录音设备是否选对（界面「设置」页可换）。

**③ 快捷键是否对？**
微信输入法 Windows 版的默认快捷键是**长按 `Ctrl+Win`**。
打开微信输入法「设置 → 语音输入」确认一下，如果不是，就在本程序
「设置」页把「语音输入快捷键」改成一样的。

**④ 目标软件是否过滤模拟按键？**
用下面的工具测一下某个组合键能否触发：

```bash
python tools/key_combo_test.py "ctrl+win" 240 4
```

它会自动等记事本到前台，然后按住该组合键 4 秒，并检查是否有新窗口弹出、
麦克风占用记录是否刷新。如果显示无反应，说明该软件忽略模拟按键，
本方案在它上面不成立。

## 问题 2：判定不准 / 开和关反了

**先测实际电平**（界面版点「测一次电平」，命令行跑 `--probe`）：

- 静音时峰值应该是**个位数**（通常就是 1）；
- 麦克风开时应该是**几百以上**。

如果两边数值都能明显区分，但程序判断反了 —— 这种情况在本版本不会发生，
因为状态是每次实测出来的，不做任何计数。

如果两边数值**区分不开**（例如静音 300、开启 350），说明这款耳机的
静音不是硬件切断信号，本工具不适用。

如果是底噪特别低的安静环境（开启时峰值也只有几十），
把「静音判定阈值」调小，例如 4 或 2。

## 问题 3：说话时键盘变得不正常

这是**设计使然**，不是 bug。

微信输入法 Windows 版的语音输入是"长按 Ctrl+Win 说话"，
所以程序必须在整个语音输入期间真的按住这两个键。
这段时间内你敲键盘，系统会认为你在按 Win 组合键
（比如按空格会切换输入法、按 D 会显示桌面）。

**应对**：说话时别敲键盘，说完把开关拨回「静音」即可。

---

## 问题 4：键盘像被 Win 键卡住了

**原因**：程序正常退出（包括 Ctrl+C）会自动松开按键。
但如果用**任务管理器强杀进程**或断电，正在按住的键会残留在按下状态。

**恢复**（任选其一）：

- 界面版点「紧急松开按键」按钮；
- 运行 `scripts\紧急松开按键.cmd`；
- 手动按一下**左 Ctrl** 和**左 Win** 键，各按一次即可清除残留状态。

---

## 问题 5：提示"已经有一个桥接程序在运行"

程序用命名互斥体做了单实例保护，避免两个实例同时工作导致按键被重复触发。

检查是不是还开着：任务管理器里找 `pythonw.exe`（源码运行）
或 `HECATE G2 语音开关.exe`（打包版）。

**注意**：请用正常方式关闭（界面版点关闭按钮、命令行版 Ctrl+C），
不要直接强杀，否则可能留下卡住的按键（见问题 4）。

---

## 问题 6：拔插耳机之后

不需要任何操作。程序每 2 秒重试一次连接，插回来后自动接上，
并且会重新实测开关位置，不会错位。

如果拔掉时语音输入正处于开启状态，程序会先松开快捷键再等待重连。

---

## 问题 7：界面版没有控制台，怎么排查？

打包后的 exe 是窗口程序，没有控制台输出。用这两个参数，结果会弹窗显示：

```bash
"HECATE G2 语音开关.exe" --list      # 列出消费类 HID 设备
"HECATE G2 语音开关.exe" --probe     # 连测三次麦克风电平
```

结果同时写入 `%APPDATA%\HecateG2VoiceBridge\cli_output.txt`。

另外 `--selftest` 参数可以做一次完整自检（tkinter、设备枚举、HID 打开、
麦克风采集），结果写入同目录的 `selftest.txt`，适合排查"换了台电脑就用不了"。

---

## 问题 8：想彻底恢复干净

程序不写注册表、不装服务、不改系统设置。要彻底清理：

1. 界面版「设置」页取消勾选「开机自动启动本程序」，保存；
   （或运行 `scripts\卸载开机自启.cmd`）
2. 删除 `%APPDATA%\HecateG2VoiceBridge\` 目录；
3. 删掉程序本体即可。

---

## 仍然不行？

请把日志（`g2_bridge.log`）和下面两条命令的输出一起附上：

```bash
python tools/hid_probe.py caps
python src/g2_voice_bridge.py --list
```
